Landschaften — „Label ausblenden“ statt „Label löschen“

Fall #80 / #81 (Thomas): Wer im Landschaftsmodus ein Label löscht, verliert die Fläche mit. Owner-Entscheid: Fläche löschen nimmt das Label mit — mit Warnung. Label löschen deaktiviert nur die Anzeige (show_name = false). Damit kann kein Editor mehr versehentlich eine Landschaft verlieren, und der Knopf verspricht, was er tut.

1 · Am Label — das floating Popup

Der Eintrag heißt „Label ausblenden“, sobald es das letzte Label einer Landschaftsfläche ist. Dasselbe Muster, das die Außenhüllen schon fahren (deleteLabel: isSourceless ? "Außenhülle löschen" : "Löschen").

3 · Was das im Code heißt

  • Ein Client-Löschweg, zwei Auslöser: deleteLabelEntry (map-features-labels.js:915), erreicht über den Popup-Knopf und deleteActiveLabel. Keine Vier-Erzeuger-Falle — nachgezählt, nicht vermutet.
  • Die Weiche fragt, was es schon gibt: ecosystemRegionOfLabel + ecosystemLabelCountOfRegion. Ist es das letzte Label einer Fläche → update_label mit show_name: false statt delete_feature.
  • Der Server schreibt nur, was mitkommt (array_key_exists, features.php:3223) — der Aufruf braucht public_id, text, feature_subtype, show_name. Keine Revision, kein Vollsatz.
  • Die Beschriftung entsteht im Menübauer (js/ui/popups.js:774), nicht im Löschweg.
  • 💣 Ein bereits ausgeblendetes Label bleibt ausgeblendet — endgültig weg ist es nur über „Fläche löschen“. Owner-Entscheid: wer die Fläche behält, behält auch ihr Label.
  • 💣 ecosystem_area hat keinen Verbergen-Schalter (is_active ist Löschen, is_trial ist seit 01.08. tot). Absichtlich: eine unsichtbare Fläche wirkt weiter — in ecosystem_region_overlap, path_ecosystem, „Was ist hier?“, den Klimazonen und im Reisegelände.
